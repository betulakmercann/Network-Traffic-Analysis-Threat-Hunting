# Network Traffic & IOC Analysis

In this study, web traffic analysis was conducted using Wireshark on the `http-chunked-gzip.pcap` capture file, suspicious/unexpected client activities on the network were examined, Indicators of Compromise (IOCs) were obtained, and these findings were mapped onto the MITRE ATT&CK matrix.

## 1. Packet & Network Metadata

- **Analyzed File:** `http-chunked-gzip.pcap`
- **Inspection Tool:** Wireshark v4.x
- **Primary Protocol:** HTTP (Hypertext Transfer Protocol)
- **Transport Protocol:** TCP (Port 8080)
## 2. Detailed Forensic Findings

### A. HTTP Request & Response Analysis

- **Request Line:** `GET / HTTP/1.1`
- **Target Host:** `www.wireshark.org:8080`
- **User-Agent:** `curl/7.46.0`
    
    - _Analysis Note:_ The client using a command-line tool (`curl`) instead of a standard web browser (Chrome/Firefox) indicates that the traffic was generated by an automated script or an external data fetching utility.
        
- **Server Header:** `cloudflare-nginx`
- **Set-Cookie Header:** `__cfduid=d8d37b52eaa3137bdfd7fd67a4ffc8a7a1452112929`
- **Transfer & Encoding:** `Transfer-Encoding: chunked`, `Content-Encoding: gzip`
    
    - _Analysis Note:_ The server response was carefully inspected against potential firewall/IDS evasion risks, confirming that the HTTP body was transferred in chunks (`chunked`) and compressed via Gzip.

## 3. Identified Indicators of Compromise (IOCs)

|Categorization|Indicator Value|Description / Context|
|---|---|---|
|**Domain Name**|`www.wireshark.org`|Target web domain address|
|**Destination Port**|`8080`|Alternative port used for HTTP traffic|
|**User-Agent String**|`curl/7.46.0`|Client identity information (CLI Tool)|
|**Cookie Data**|`__cfduid=d8d37b...`|Cloudflare session/identification cookie|
|**HTTP Request URI**|`/`|Target root directory requested|

## 4. MITRE ATT&CK Mapping

|Tactic|Technique ID|Technique Name|Operational Context|
|---|---|---|---|
|**Command and Control**|**T1071.001**|Application Layer Protocol: Web Protocols|Client and server communicating via HTTP protocol over a non-standard port (8080).|
|**Command and Control**|**T1008**|Fallback Channels|Likelihood of using an alternative port (8080) to evade network controls.|
|**Resource Development**|**T1588.002**|Obtain Capabilities: Tool|Usage of the `curl` command-line utility on the client side to fetch data.|
|**Execution / Transfer**|**T1105**|Ingress Tool Transfer|Downloading content/data from an external server using the HTTP GET method.|

## 5. Recommendations & Mitigation Strategies

1. **User-Agent Based Egress Filtering:** Direct external internet access for automation and CLI tools (`curl`, `python-requests`, `powershell`) other than known browsers should be restricted for outbound network connections.
    
2. **Port-Based Traffic Monitoring:** Outbound traffic destined for 8080 and similar alternative HTTP ports should be added to SOC monitoring rules.
    
3. **Deep Packet Inspection (DPI):** HTTP responses transmitted in Gzip or chunked formats must be decompressed and decrypted at the network layer to ensure content scanning.
